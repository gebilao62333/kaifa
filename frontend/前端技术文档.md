## 1. 项目概述

### 1.1 项目简介

eu搭子是一个游戏陪玩 / 休闲社交平台的前端项目。当前版本基于 **Vue 3 + Vite 5** 构建，是一个纯 SPA（单页应用），在浏览器端运行，**不依赖 UniApp 框架**。

项目采用组件化架构，核心页面已拆分为独立组件，通过底部 Tab 导航实现首页、广场、消息、我的四个主视图切换，并通过弹层系统实现发布动态、评论系统、用户资料查看、预约陪玩、陪玩师申请、钱包管理、个人资料编辑、帮助反馈、设置等次级功能。

### 1.2 产品定位

- **目标用户**：游戏玩家、陪玩师（陪陪）
- **核心价值**：连接游戏玩家与陪玩师，提供线上/线下陪玩服务
- **主要功能**：主页浏览、陪玩申请（线上/线下）、即时聊天、圈子互动、钱包管理、个人资料编辑

### 1.3 架构概览

## 4. 核心功能模块

### 4.1 用户认证模块

- **登录/注册**：手机号验证码登录（发送验证码 `/api/user/send-sms`、登录 `/api/user/login-mobile`）、密码登录、密码重置
- **第三方登录**：`/api/user/login-third`
- **用户信息**：获取用户信息 `/api/user/get`、更新资料 `/api/user/update`
- **等级经验**：`/api/user/level`（等级/进度/VIP 加速倍率/经验来源/权益清单）、`/api/user/level/check-in`（每日签到，自然日去重）；`LevelAcceleration.vue` 全量接口驱动，无本地硬编码曲线
- **Token管理**：`store/user-info.js` 的 `extractToken()` 只取 `data.accessToken || data.token` 并写入 `STORAGE_KEYS.TOKEN`；**后端返回的 `refreshToken` 前端从不落盘、`/api/user/refresh-token` 也没有任何调用方**（v7.17 校正：本行旧文案写「存储与自动刷新」与代码不符）。实际口径是——访问令牌 `type=access` 有效期内直接用，过期后由 `common.js` 的 401 分支清登录态并跳 `/login` 重新登录，无静默续期

- **金币口径以服务端为准**：入账数量只取下单时写进 `xn_order_chong.coins` 的值，前端不参与计算；支付成功后仍调用 `getWalletBalance()` 刷新真实余额。

## 9. 错误码定义

| 错误码 | 说明 | 处理方式 |
|--------|------|----------|
| 200 | 请求成功 | 正常处理 |
| 201 | 创建成功 | 正常处理 |
| 400 | 请求参数错误 | 提示用户检查输入 |
| 401 | 未授权/Token过期/令牌用途不符/**令牌已被吊销（H-5：登出、改密、封号后）** | 跳转登录页（后端文案「令牌已失效」同样走这条分支，前端无需特判） |
| 403 | 权限不足/账号禁用/禁言 | 提示对应原因 |
| 404 | 资源不存在 | 提示资源不存在 |
| 422 | 业务逻辑错误 | 显示后端返回的具体错误信息（如密码错误、用户不存在等） |
| 429 | 请求频率限制 | 提示操作过于频繁，稍后重试 |
| 500 | 服务器错误 | 提示系统繁忙 |
| 503 | 依赖服务不可用（**H-5 起含「吊销状态无法确认」**：生产 fail-closed 下 Redis 抖动会让需登录的接口、登出、改密、后台删号统一 503；H-3 的后台登录防爆破校验失败也是 503） | 透传后端 `message`（v7.18 起 `!response.ok` 分支解析响应体，此前显示「请求失败 (503)」）；C 端 `logout()` 与管理端 `signOut()` 都已 `.catch`，**503 不阻塞本地清理**，代价是令牌在后端 fail-closed 窗口内可能仍可用 |
| 502 | 网关错误 | 提示稍后重试 |
