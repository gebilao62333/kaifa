## 1. 全局交互架构（横切能力）

### 1.1 应用外壳（`src/main.js` + `src/App.vue`）

app 根组件（`App.vue`）固定挂载这些全局交互，构成“外壳层”：

| 挂载物 | 作用 | 关键交互 |
|---|---|---|
| `ErrorBoundary` → `router-view` | 页面渲染容器 | 路由切换时套 `transition name="page"`（淡入 + 8px 横向位移），以 `route.path` 为 key |
| `BottomNav` | 底部 Tab 栏 | 仅当 `!route.meta.fullscreen && path !== '/login'` 时显示 |
| `Toast` | 全局提示 | `v-bind="toast.state"`，由 `useToast` 单例驱动 |
| `IncomingCall` | 来电浮层 | `socketService.on('call_invite')` 触发 `showIncomingCall()` |
| `NetworkStatus` | 网络状态条 | 断网/慢网横幅 |
| `SplashPopup` | 开屏弹窗（管理员投放位） | `App.vue onMounted` → `loadSplash()` → `homeService.getSplashList()`（`GET /api/splash/active`）→ `utils/splashScreen.js` 按 `frequency`（1 每次打开 / 2 每天 / 3 每周 / 4 仅一次）用 `localStorage` 去重，一次启动只弹排序最靠前的一条未到去重周期的；`Teleport` 遮罩 + 淡入，点卡片有 `link` 则跳转（`http(s)` 走 `location.href`，站内走 `router.push`），无 `link` 或点遮罩/右上角 ✕ 均关闭；图片加载失败回退 `genCover` 占位图 |

桌面端适配：非沉浸式页用 `.route-shell--frame` 约束到 650px / 720px 居中；`modal-overlay` 同宽对齐。

**启动时交互**：
- `userStore.initFromStorage()` — 从 localStorage 恢复 token / profile，并自愈脏数据（balance/score 强制转数字）。
- `setupP2PFetchResponder()` — 注册 P2P 取流响应方（一次）。
- `loadSplash()` — 拉取开屏弹窗（见上表）；登录态与否都可展示（管理员面向全服投放），接口失败静默，不阻塞首屏。
- 全局错误拦截：捕获阶段 + 冒泡阶段双注册 `error`、`window.onerror`、`unhandledrejection`，**抑制浏览器扩展/跨域脚本注入产生的噪音错误**（`Script error.`、`getBoundingClientRect(null)` 等），避免 WebView 弹错。

### 1.2 路由系统（`src/router/index.js`）

- 模式：`createWebHistory`；根 `/` 重定向 `/home`。
- **懒加载**：所有页面 `() => import('../views/XXX.vue')`。
- **全局前置守卫 `beforeEach`**：
  - 公开路由（白名单）：路由名 `PUBLIC_ROUTE_NAMES`（Login/Home/Search/Square/PostDetail/Preferred/Mine/Friend）或路径前缀 `PUBLIC_ROUTE_PATHS`（`/`、`/login`、`/home`、`/search`、`/square`、`/friend`）。
  - 非公开路由或 `meta.requiresAuth === true` 且无有效 token → 重定向 `Login` 并带 `?redirect=fullPath`。
  - token 有效性判定：`localStorage.token` 且不为 `'undefined'/'null'`，否则回退 store.token。
- **后置钩子 `afterEach`**：
  - `meta.title` → `document.title = "{title} - eu搭子"`。
  - `meta.preload`：Home 页预加载 `Login`、`Search` 组件。
- **滚动行为**：有 `savedPosition` 恢复；否则回顶 `{ top: 0 }`。
- **沉浸式页**：`meta.fullscreen`（Login、ChatRoom、VideoCall、AudioCall、CustomerService、VirtualUserList/AIChat）→ 隐藏底部导航。
- **鉴权页**：`/ai-chat`、`/ai-chat/:id`、`/tag-manager` 显式 `requiresAuth: true`。

> 未注册独立路由的视图：`OnlineCompanion.vue`、`OfflineCompanion.vue`（由 `CompanionApply.vue` 内嵌使用）。

### 1.3 全局状态与持久化

**Pinia Store（2 个）**

- `useUserStore`（`store/user-info.js`）：token / profile / configInfo；getters 提供 `isLogin / isVip / userId / nickName / avatar / level / vipLevel / balance / score / fansCount / gender / region / signature / phone`；actions 覆盖登录（密码/验证码/第三方）、注册、重置密码、发短信、拉取/更新资料、关注/取消关注（本地增减 followCount）、余额增减、logout、`initFromStorage`、`checkAndRefreshUserInfo`。⚠️ H-5 起 `logout()` 不再是纯本地动作：它先同步发起 `POST /api/user/logout`（服务端吊销），再清 state/token/持久化并断开 socket，最后把该 promise 返回给调用方（失败已被 `.catch` 兜成 `null`，不会 reject）。

**深色模式**：`Settings` 切换时写 `localStorage('darkMode')` 并对 `documentElement` 增删 `.dark` 类；`PageLayout` 等已内置 `.dark` 覆盖。

### 1.4 网络请求层（`src/common/common.js`）

统一 `request(url, method, data, headers, timeout=15000, options)`：

- 自动附 `Authorization: Bearer {token}`；`cache: 'no-store'`；`AbortController` 超时终止。
- GET 参数拼 query，其余 `JSON.stringify` body。
- **响应码 → 交互**：
  - `401`：仅当 `options.requireLogin` 时清理 token 并跳 `/login`（防公开页误跳）；抛 `RequestError`。触发原因除「未登录 / 令牌过期」外，自安全扫描 H-4 起还包含「令牌用途不符」（服务端按 JWT `type` 声明做边界校验，见《前端技术文档》v7.17 §4.10），自 H-5 起还包含「**令牌已被吊销**」（本端登出、改密、被封号后旧令牌命中服务端黑名单/水位线，文案为「令牌已失效」），前端都不区分、统一走重登。**503 不会触发跳转**：H-5 后生产 Redis 不可确认时鉴权与登出都可能返回 503，它落进 `request()` 的通用非 2xx 分支——本轮该分支改为**解析响应体并透传后端 `message`**（与 v7.16 管理端同口径，此前一律显示「请求失败 (503)」，「登出服务暂时不可用，请稍后重试」这类可读提示被吞掉；响应体非 JSON 时保留默认文案），不整页跳转；登出链路另有 `.catch` 兜底保证本地态清干净。
  - `404` → “请求的资源不存在”；`422` → 解析 `errors` 字段为 `fieldErrors`（登录页据此拼装中文字段错误）；`500` → 尝试读后端 message，否则“服务器繁忙”；其余非 ok → **H-5 起（v7.18）也先解析响应体透传 `message`**（此前一律 `请求失败 (status)`），非 JSON 时才回落到 `请求失败 (status)`——这样 429（登录限流）与 503（吊销状态不可确认）的可读提示才能到用户眼前。
  - 业务码非 `0/200` → 抛 `RequestError(message, code)`。
  - `AbortError` 默认静默（`silentAbort`），避免页面跳转时报错。
- 工具函数：`formatTime / formatDuration / formatBalance / formatNumber / debounce / throttle / getLevelName / getVipName / getOrderStatusText / getReserveStatusText / getCallStatusText / getAuditStatusText / validateMobile / validateEmail / validatePassword / validateNickname / validateRequired / validateNumber / validateStringLength / validateParams / isLoggedIn / checkLoginStatus / RequestError`。

### 1.5 文件上传（`src/services/uploadService.js`）

`uploadFile(file, type, onProgress)`，两段式：

1. **前端直传 COS（优先）**：`GET /api/upload/token?type&ext` 取预签名 → `XMLHttpRequest PUT` 直传（带进度回调）→ `POST /api/upload/register` 登记 URL 索引。
2. **后端中转兜底**：COS 失败回退 `POST /api/upload/image|audio|video`（按 type 选端点，`overrideMimeType` 修中文乱码）。

附带 401 → 清 token 跳登录；导出 `uploadImage / uploadAudio / uploadVideo`。使用方：EditProfile（头像/背景）、ChatRoom（图片/视频）、PublishPost、Feedback、report-modal、MyAlbum（经 `albumService.uploadPhoto`）、RealName（证件照，`dataUrlToFile` 后上传）、MyServices / CompanionApply（`icon` 图 + `voiceIntro` 语音，`urlToFile` 后上传）、Withdraw（收款码，2026-10-04 起选图即直传，见 §3.5）等。

### 1.6 实时通信（`src/services/socketService.js`）

单例 `socketService`，Socket.IO：

- `connect(url)`：`auth: { token }`，`transports: ['websocket','polling']`，重连 1s→5s、最多 5 次、超时 10s。
- `connect_error === 'UNAUTHORIZED'` → 断开、清 token、跳 `/login`（避免无限重试）。
- `on / off / emit` 封装；`connected` 为响应式 ref。
- 默认监听 `call_invite / call_accept / call_reject / call_end`（仅日志）。
- **客户端事件**（`emit`）：`private_message`（实际发送走 REST，未用）、`call_invite / call_cancel / call_reject / call_accept / call_end`、`webrtc_offer / webrtc_answer / webrtc_ice_candidate`、`p2p_fetch_request / p2p_offer / p2p_answer / p2p_ice_candidate`、`typing`、`revoke_message`、`message:read`。
- **服务端事件**（`on`）：`private_message / message:read / message:revoked`（ChatStore 消费）、`typing / message_revoked`（ChatRoom 消费）、`call_*`（App / IncomingCall / 通话页消费）、`p2p_*`（p2pFetchService 消费）、`error`。

### 1.7 P2P 取流（`src/services/p2pFetchService.js`）

WebRTC DataChannel 点对点回传小文件（头像/缩略图），减轻服务器带宽：

- 响应方（`setupP2PFetchResponder`）：收到 `p2p_fetch_request` → 建 PeerConnection + DataChannel → `fetch(url)` 取字节回传；失败回退发送 `{ fallbackUrl }`。
- 请求方（`p2pFetch({peerId,url,type,timeout})`）：先 `GET /api/p2p/peer-online` 探活，不在线直接回退签名 URL；在线则交换 `p2p_offer/answer/ice`，8s 超时回退。
- 任何一步失败都回退常规 URL（可用性优先）。

### 1.8 音视频通话（双通道：TRTC 主 / WebRTC 备）

**`callService`（统一入口，自动选通道）**

- `isTRTCAvailable()`：`GET /api/trtc/auth` 返回 `appId` 则用 TRTC，否则 WebRTC（结果缓存）。
- `startCall(calleeId, callType)`：TRTC 走 `trtcService.startCall` (`POST /api/trtc/start`) + `socket.emit('call_invite',{useWebRTC:false})`；WebRTC 走 `_startWebRTCCall` → `POST /api/trtc/start` 建记录 + `webrtcCallService.initiateCall`。
- `acceptCall({callId,callerId,callType,useWebRTC})`：按 `useWebRTC` 选 TRTC accept 或 `webrtcCallService.handleIncomingCall`。
- `rejectCall / cancelCall / endCall`：TRTC REST + `socket.emit('call_reject'|'call_cancel'|'call_end')`。
- `startDurationTimer()`：每秒 `onDurationTick(duration)` 驱动通话计时与计费。
- `toggleAudio / toggleVideo`：仅 WebRTC 分支生效（TRTC 由页面直接切流）。
- 回调：`setCallbacks({onDurationTick, onCallEnd})`。

**`webrtcCallService`（原生通道）**：`RTCPeerConnection` + Google STUN；状态机 `idle → calling/ringing → connecting → connected → disconnected/failed/ended`；主叫 `initiateCall`（先 `call_invite{useWebRTC:true}`，接听后 `sendDelayedOffer` 发 `webrtc_offer`），被叫 `handleIncomingCall`（主动 createOffer + `call_accept`）；`handleOffer/Answer/IceCandidate`（`pendingCandidates` 缓存先到的 ICE）；`toggleAudio/Video` 切轨道 enabled；`hangup` 清理媒体并发 `call_end`。

**`trtcService`（腾讯云通道）**：REST 封装 `/api/trtc/{auth,start,cancel,reject,accept,end,history,room/*,billing/*}`。

**来电浮层 `IncomingCall`**（全局）：见 [2.3](#23-功能弹层用组件)。

### 1.9 权限与网络状态

- `composables/usePermissions.js`：相机/麦克风权限查询（`navigator.permissions`）、请求（`getUserMedia`）、状态缓存到 localStorage；按浏览器（Chrome/Edge/Safari/Firefox）生成**分步授权引导文案** `getPermissionGuideSteps()`；错误类型归一化（denied/not_found/in_use/not_supported）。
- `utils/networkStatus.js` + `NetworkStatus.vue`：监听 `online/offline` 与 `navigator.connection.change`，暴露 `isOnline / effectiveType / isSlowNetwork()`；驱动全局横幅（见 [2.3](#23-功能弹层用组件)）。

### 1.10 自定义指令

- `v-lazy`（`directives/lazyLoad.js`）：`IntersectionObserver` 懒加载，`rootMargin` 默认 50px，进入视口后 `dataset.src → src` 并停止观察；`updated` 重新观察、`unmounted` 断开。
- `v-img-fallback`（`directives/imgFallback.js`）：`error` 时用 `genAvatar(name)` 生成 SVG 头像兜底（一次性）。

## 5. 状态机与常量字典

**消息状态**（`STATUS.MESSAGE`）：`sending / sent / failed / read / recalled`。

**订单状态**（`STATUS.ORDER`）：0 待接单 / 1 已接单 / 2 进行中 / 3 已完成 / 4 已取消 / 5 申诉中。

**预约状态**（`STATUS.RESERVE`）：0 待确认 / 1 已确认 / 2 已拒绝 / 3 已完成 / 4 已取消 / 5 申诉中。

**通话状态**（`STATUS.CALL`）：0 呼叫中 / 1 已接通 / 2 已拒绝 / 3 已取消 / 4 已结束 / 5 无应答 / 6 异常。

**审核状态**（`STATUS.AUDIT`）：0 未认证 / 1 审核中 / 2 已认证 / 3 已拒绝。

**WebRTC 通话态**：`idle / calling / ringing / connecting / connected / disconnected / failed / ended`。

**消息类型**（`MESSAGE_TYPES`）：text / image / video / audio / location / gift / redpacket / system（发送码：text 0 / audio 1 / image 2 / video 3 / location 4 / gift 5 / redpacket 6）。

**等级**（`LEVELS`）：1 新手 … 10 王者；**VIP**（`VIP_LEVELS`）：VIP1–VIP5。

**分页**：默认 page=1、pageSize=20、最大 100（`PAGINATION`）。

**定时器**（`TIMERS`）：轮播 3000ms、防抖/节流 300ms、Toast 2000ms、心跳 30000ms、重连 1000→5000ms。

**API 错误码→交互**：200/201 正常；400 参数；401 跳登录；403 权限/禁用/禁言；404 不存在；422 业务/字段错误；429 频繁；500 服务器繁忙；502 稍后重试。

### 6.6 预约/订单状态机相关（2026-10-05 安全扫描 H-7 后新增）

27. **MyOrder**：`item.rated` 无服务端来源（列表接口 `formatOrder` 只回 `star`/`content`，不回 `pingjia_status`），「已评价」只在提交成功后于内存标记，刷新即失效——重复评价的入口在 UI 上重新出现，只靠服务端拒绝兜底（返回「该订单已评价」，但见 #28 的状态码问题）。可行的最小修法：前端改判 `item.star > 0`，或后端在 `formatOrder` 里补 `rated: order.pingjia_status === 1`。
28. **MyOrder**：`submitRating` 的 catch 丢弃服务端 message，固定提示「评价失败，请重试」；且该接口对业务错误返回 **HTTP 500**（控制器 `evaluateOrder` 只分流 404「订单不存在」/403「无权评价他人订单」），前端无法按状态码区分。建议：后端补 `pingjiaStatus` 并统一 422，前端改用服务端值并直出 message。
29. **MyOrder / MyReserve**：状态迁移失败（他人已先完成/取消）时**只在成功分支刷新列表**，失败分支仅 toast，因此列表可能停留在过期状态、用户需要再点一次才看到业务错误。建议失败分支同样触发一次加载。
30. **预约的接单方流程无 UI**：`reserveService.confirmReserve / rejectReserve / completeReserve` 与 `toggleSlot`（时段开关）在 `frontend/src/views` 下均无调用点（`MyReserve.vue` 只用 `getReserveList` 与 `cancelReserve`），陪玩师的预约确认/拒绝/完成与时段管理当前只能走接口，页面未接。`toggleSlot(slotId, enabled)` 上送的 `enabled` 后端从不读取（语义为「按当前状态取反」）。
