## 1. 项目概述

### 1.1 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| **前端框架** | Vue 3 (`<script setup>` Composition API) | 组件化 SPA，57 个视图组件 + 16 个公共组件 |
| **构建工具** | Vite 5 | 开发服务器端口 5174（`npm run dev`，见 `vite.config.ts`） |
| **路由** | Vue Router 4 (createWebHistory) | 54 条路由配置，含登录守卫、预加载策略 |
| **状态管理** | Pinia 2 | `store/user-info.js`（用户）、`store/chat.js`（聊天未读），配合持久化插件 `plugins/persistedState.js` |
| **HTTP 请求** | 原生 fetch + 自封装 request | `common/common.js` 统一封装，JWT Token 自动携带 |
| **实时通信** | Socket.IO Client | `services/socketService.js` 封装，支持自动重连 |
| **音视频** | TRTC（主通道）+ WebRTC（备选通道） | `callService.js` 统一调度，双通道自动切换 |
| **文件上传** | COS 预签名直传 + 后端中转兜底 | `services/uploadService.js` |
| **后端** | Node.js + Express | RESTful API + Socket.IO |
| **支付** | 微信支付 / 卡密充值 | `services/payService.js` |

### 1.2 架构概览

前端已从早期"单文件 App.vue + 条件渲染 + 纯 Mock"演进为标准的 **Vue Router + Pinia + services 分层架构**：

- **App.vue（约 307 行）** 仅是路由壳组件：`<router-view>` 页面切换 + `BottomNav` 底部导航 + `Toast` 全局提示 + `IncomingCall` 来电提醒 + `NetworkStatus` 网络状态 + `SplashPopup` 开屏弹窗（启动时拉 `GET /api/splash/active`）+ 登录后 Socket.IO 初始化 + 主 Tab 横滑手势
- **页面切换** 由 Vue Router 管理（`router/index.js`，54 条路由），不再使用 `currentTab` 条件渲染
- **全局状态** 由 Pinia Store 管理（用户信息、聊天未读数），并持久化到 localStorage
- **接口调用** 全部收敛到 `services/` 层（30 个服务文件），视图组件不直接拼接请求
- **已接入后端 API 与 Socket.IO**，登录、聊天、钱包、充值、通话、礼物、举报等核心链路均为真实后端对接

```text
┌──────────────────────────────────────────────────────────────┐
│                   浏览器端 (Vue 3 SPA)                        │
│  App.vue(路由壳) → RouterView → 57 个视图组件 (views/)       │
│  + 16 个公共组件 (components/) + 30 个服务 (services/)        │
│  + Pinia Store (user-info / chat)                            │
└──────────────────────────────────────────────────────────────┘
                             │
              fetch(request) / Socket.IO / COS 直传 / WebRTC
                             │
┌──────────────────────────────────────────────────────────────┐
│                   后端服务层 (Express.js)                     │
│  RESTful API → Controllers → Services → MySQL / MongoDB      │
│  Socket.IO 实时通讯 / 腾讯云 TRTC 音视频 / COS 对象存储       │
└──────────────────────────────────────────────────────────────┘
```

### 1.4 路由与导航

**底部 TabBar（BottomNav）**：首页 `/home`、广场 `/square`、消息 `/preferred`、我的 `/mine`。

- `afterEach` 设置页面标题，首页预加载 `Login`、`Search` 组件

### 2.1 用户认证模块

**状态**: ✅ 已对接后端

**文件位置**: `views/Login.vue` + `store/user-info.js` + `services/authService.js`

| 功能点 | 状态 | 说明 |
|--------|------|------|
| 密码登录 | ✅ | `authService.login` → `/api/user/login` |
| 短信验证码登录 | ✅ | `sendSms` → `/api/user/send-sms`，`loginMobile` → `/api/user/login-mobile` |
| 注册 | ✅ | `/api/user/register` |
| 密码重置 | ✅ | `/api/user/reset-password` |
| 第三方登录 | ✅ | `/api/user/login-third` |
| Token 管理 | ⚠️ 部分 | 只存 `accessToken`（`type=access`）于 localStorage + Pinia，请求自动携带，401 清登录态并跳转登录页。后端返回的 `refreshToken` **前端从不落盘**，`/api/user/refresh-token` 无调用方 → 没有静默续期，令牌到期就要重新登录（`JWT_EXPIRES_IN` 默认 7d）。安全扫描 H-4 起跨用途令牌（refresh / 管理员）在后端直接 401/403；H-5 起旧令牌还可能被**服务端吊销**（登出/改密/封号），命中时同样是 401 → 走既有清理分支 |
| 服务端登出 | ✅（H-5 新增） | `authService.logout()` → `POST /api/user/logout`，固定带 `{ logoutAllDevices: true }`（C 端不存 refreshToken，只拉黑 access 会留一枚 30 天可换新的孤儿凭据，故走水位线），5 秒超时 + `silentAbort`。⚠️ **用户端登出＝全端下线**，不是单设备。`store/user-info.js` 的 `logout()` **先发起请求、后清本地态**（`request()` 在同步阶段读 `localStorage` 拼 `Authorization`，顺序反了就是未认证请求），失败 `.catch(() => null)` 不阻塞清理并返回 promise |
| 登录状态持久化 | ✅ | `userStore.initFromStorage()` 应用启动时恢复 |
| 获取/更新用户信息 | ✅ | `/api/user/get`、`/api/user/update` |

### 2.19 管理后台模块 (Admin)

**状态**: ✅ 已对接后端（独立项目）

**文件位置**: 管理后台**不在本前端项目中**，位于仓库根目录的独立项目 `admin-frontend/`（22 个管理页面 + `AdminLogin` 登录 + `NoPermission` 无权限 + `AdminLayout` 布局），通过 `/api/admin`、`/api/admin-manage` 等后端接口对接。

主要页面：AdminDashboard（仪表盘）、AdminUsers（用户管理）、AdminOrders（订单管理）、AdminPosts（动态管理）、AdminWithdraws（提现审核）、AdminReports（举报处理）、AdminFinance（财务管理）、AdminRechargePackages（充值套餐）、AdminSplashCarousel（开屏轮播）、AdminRecommend（推荐管理）、AdminVipPackages、AdminGifts、AdminGiftLogs、AdminRecharges、AdminGames、AdminCompanionApps、AdminVirtualUsers、AdminAdmins、AdminRoles、AdminApi、AdminSettings、AdminCards 等。

**登录链路（安全扫描 H-3，v6.18）**：后端给 `/api/admin/login` 与 `/api/admin-manage/login` 加了单 IP 限流（15 分钟 5 次）与账号失败锁定（Redis 连续失败 5 次锁 15 分钟，两个入口共用同一计数键），超限回 429（带 `data.retryAfterSec`），Redis 不可用回 503。管理端配合改动只有一处——`src/common/common.js` 的 `request()` 兜底分支改为解析响应体并透传后端 `message`（此前非 2xx 一律显示「请求失败 (429)」，锁定提示与恢复时间被吞）。`AdminLogin.vue` 的 `catch` 早已渲染 `err?.message`，**登录页零改动**即可显示「登录失败次数过多，请 N 分钟后再试」。**遗留**：未把 `data.retryAfterSec` 做成本地倒计时禁用提交按钮，被锁期间管理员仍可反复点击并每次吃到 429；无登录失败审计视图。

**会话终止（安全扫描 H-5，v6.20）**：`adminService.signOut()` 是唯一的退出入口，做三件事——①先用 `admin_token` 发 `POST /api/admin/logout`（`request()` 在同步阶段读 `localStorage` 拼 `Authorization`，所以**必须先请求后清理**），并把 `admin_refresh_token` 作为 `body.refreshToken` 上送，后端核验 `type=admin_refresh` 且 `id` 归属本人后一并作废；②立刻清 `admin_token` / `admin_refresh_token` / `admin_user` 三件套；③`logout()` 带 5 秒超时与 `skipAuthRedirect`（登出接口自己回 401/503 时不该再整页跳转），且**不 await 网络结果**，避免吊销服务抖动把管理员卡在「退出中」。调用方 `AdminLayout.vue`（顶栏退出，随后 `router.push('/login')`）与 `NoPermission.vue` 此前只 `localStorage.removeItem('admin_token')`，权限快照与 refresh 留在浏览器里，本轮统一改走 `signOut()`；`common.js` 与 `AdminDashboard.vue` 的 401/失效兜底分支同样清三件套。**遗留**：`ADMIN_TOKEN` 应急固定令牌走后端 `revocable:false` 分支，登出只清本地态、无法服务端吊销；管理员改自己的 `permissions`/`role_id` 后端不做吊销（避免自踢），需重新登录才生效。
