## P0 资金与核心链路阻断（建议先修）

### P0-1 充值下单 / 回调整链字段错位（`xn_order_chong`）

**位置**
- `src/services/payService.js` → `createOrder`、`wxPayCallback`、`getPaymentHistory`
- `src/services/wechatPayService.js` → `createUnifiedOrder`、`handleNotify`

**现状（对照 `OrderChong` 模型 = `xn_order_chong` 表）**

表真实列：`order_no, user_id, amount(NOT NULL), coins(NOT NULL), status, pay_type, pay_time, create_time, update_time`。**没有** `cid / money / gold_coins / currency / pay_no`。

| 代码位置 | 写入/读取 | 问题 |
|---|---|---|
| `payService.createOrder` | `cid, money, gold_coins, currency` | 未知字段被 Sequelize 忽略；NOT NULL 的 `amount`、`coins` 未写 |
| `wechatPayService.createUnifiedOrder` | `cid, money` | 同上 |
| `payService.wxPayCallback` | `pkg = RechargePackage.findByPk(order.cid)` | `order.cid` 为 undefined → `pkg` 为 null → `pkg.coins` 抛错 |
| `wechatPayService.handleNotify` | `order.cid`、`order.update({pay_no})` | 同样读不到套餐；`pay_no` 列不存在 |
| `payService.getPaymentHistory` | `order.money`、`order.gold_coins` | 字段不存在，返回 undefined |

**影响**：`POST /api/pay/create-order`、`/wx-order`、`/pay/create` 触发 `SequelizeValidationError: notNull Violation`（500）；即使建单成功，回调也无法加币。

**修复方案**（最小改动，不改表）
1. `createOrder` / `createUnifiedOrder` 写：
   ```js
   amount: Number(pkg.price),
   coins: pkg.coins + (pkg.bonus_coins || 0),
   pay_type: payType,
   status: 0
   ```
2. 回调不再反查套餐，直接用订单自身金币入账：
   ```js
   await order.update({ status: 1, pay_time: getTimestamp() }, { transaction });
   await User.increment('money', { by: order.coins, where: { id: order.user_id }, transaction });
   ```
   （`transactionId` 当前无处存。可选：临时记到 `pay_type` 之外的新列，或本次先不记录，作为增强项。）
3. `getPaymentHistory` 改读 `order.amount`、`order.coins`。

**复现/验证**：`POST /api/pay/create-order {packageId}` 应返回 `orderNo`；`POST /api/pay/wx-callback {payNo, transactionId}` 后查 `xn_user.money` 增加 `coins`。

### P0-2 提现两条链路 NOT NULL 缺失（`xn_withdraw`）

**位置**：`src/services/giftService.js#withdraw`、`src/services/walletService.js#applyWithdraw`；模型 `Withdraw`。

**现状**：`money`、`amount`、`pay_money` 三列均 `allowNull:false`。

| 入口 | 写了 | 漏了（NOT NULL） |
|---|---|---|
| `giftService.withdraw`（礼物提现） | money、pay_money、shouxufei | **amount** |
| `walletService.applyWithdraw`（钱包提现） | amount、type、account… | **money、pay_money** |

**影响**：两处 INSERT 均触发 notNull 校验失败，**提现申请完全不可用**。

**修复方案**：抽一个内部函数统一落单，三列齐写，避免再次漂移：
```js
const createWithdrawRecord = (data, options) => Withdraw.create({
  user_id, 
  money: amount,          // 提现额
  amount,                 // 提现额（历史冗余列）
  pay_money: netAmount,   // 到账净额
  shouxufei: fee, type, account, bank, name, image, mobile,
  is_check: 0, status: 0, channel,
  create_time: getTimestamp(), update_time: getTimestamp()
}, options);
```
两个入口都改调它。

**验证**：`POST /api/gift/withdraw` 与 `POST /api/wallet/withdraw` 各提交一次，检查 `xn_withdraw` 落行且三列有值。

### P0-3 钱包收入聚合字段错位（礼物 / 通话）

**位置**：`src/services/walletService.js#collectIncomeRecords`

**现状**

| 业务 | 现有 SQL | 真实列 | 问题 |
|---|---|---|---|
| 礼物 | `total_money AS amount … WHERE to_user_id` | `totalmoney`、`user_id`（收款人） | 列名全错 |
| 通话 | `b.amount`、`b.call_record_id`、`r.type`、`b.status=1` | `b.total_amount`、`b.call_id`、`r.call_type` | 列名错 |

**影响**：`/api/wallet/overview`、`/income-records`、`/income-breakdown` 恒缺礼物与通话收入，总资产偏小。

**修复方案**
```js
// 礼物（收款人为 xn_gift_log.user_id）
'SELECT id, totalmoney AS amount, create_time FROM xn_gift_log WHERE user_id = :uid'

// 通话
`SELECT b.id, b.total_amount AS amount, b.create_time, r.call_type
 FROM xn_call_billing b
 JOIN xn_call_record r ON b.call_id = r.id
 WHERE r.callee_id = :uid AND b.status = 1`
// call_type === 2 ? video : voice
```
**配套（关键）**：`src/services/callBillingService.js#createBilling` 目前写 `status: 0`，且**无人**把它改为 1，导致上面查询恒为空。由于该方法在扣款/分账的同一流程里完成，应改为 `status: 1` 并写 `settle_time`（语义=已结算）。**需先与产品确认"通话收入何时计入"**：即时入账（推荐，与现有资金流一致）还是审核后入账。

**验证**：送一次礼物 + 完成一次「陪玩通话」后，`/api/wallet/income-records` 出现礼物与通话条目。

## P3 健壮性与并发

### P3-1 扣费类并发无锁 / 无事务
- **位置**：`gamesService#createOrder`（先查余额再扣）、`#grabOrder`、`reserveService#createReserve`、`circleService#unlockPost`
- **修复**：统一改为事务 + 原子 UPDATE：
  ```sql
  UPDATE xn_user SET money = money - :amt WHERE id = :uid AND money >= :amt;
  ```
  以 `affectedRows` 判定成功；唯一键冲突（如 `xn_post_unlock` 的 `post_id+user_id`）改为**先写解锁记录再扣费**或捕获冲突回滚，避免"钱已扣、记录未落"。

### P3-2 通话计费余额不足分支递归异常
- **位置**：`src/services/callBillingService.js#createBilling`
- **现状**：余额不足时在 `endCall` 内部再次调用 `endCall`，此时通话已是 `status=4`，抛出"通话状态不正确"。
- **修复**：`createBilling` 不再回调 `endCall`，改为抛业务错误或置 `end_reason='余额不足'` 由上层处理。

### P3-3 直传扩展名无白名单
- **位置**：`src/services/uploadService.js#getDirectUploadToken`（`ext` 由前端传入）
- **修复**：服务端按类型白名单校验 `ext`，或统一改写对象键后缀。
