## 1. 部署方式概览

本项目支持两种部署方式：

| 方式 | 适用场景 | 复杂度 | 本文档章节 |
|------|----------|--------|-----------|
| **Docker Compose（推荐）** | 开发/测试/小规模生产 | 低，一键启动 | 第2-6章 |
| **传统手动部署** | 大规模生产/自定义集群 | 高 | 第7-11章 |

> **当前开发环境使用 Docker Compose 部署**，5 个容器全部 healthy，59 个 API 全部通过。

## 2. Docker Compose 部署（推荐）

### 2.1 环境要求

| 项目 | 最低配置 | 推荐配置 | 说明 |
|------|----------|----------|------|
| CPU | 2核 | 4核+ | - |
| 内存 | 4GB | 8GB+ | Docker 5 个容器共约 1.5GB |
| 磁盘 | 20GB | 50GB+ | 含镜像+数据卷 |
| 系统 | Windows 10+ (WSL2) / macOS / Linux | - | - |
| Docker | 24.0+ | 最新版 | 含 Docker Compose v2 |

### 2.2 Windows/WSL 前置准备

```powershell
# 1. 安装 WSL2（Windows 必需）
wsl --install -d Ubuntu-22.04

# 2. 安装 Docker Desktop
# 下载: https://www.docker.com/products/docker-desktop/

# 3. 验证安装
wsl --version
docker --version
docker compose version
```

### 2.3 Docker Compose 服务架构

```
                    ┌──────────────┐
                    │   用户浏览器   │
                    └──────┬───────┘
                           │ :80
                    ┌──────▼───────┐
                    │   Nginx      │  静态资源 + 反向代理
                    │   :80        │
                    └──────┬───────┘
                           │ /api/*  /socket.io/*
                    ┌──────▼───────┐
                    │   Backend    │  Node.js 18 + Express
                    │   :3000      │
                    └──┬───┬───┬──┘
                       │   │   │
              ┌────────▼┐ ┌▼───────▼┐ ┌────────▼┐
              │  MySQL  │ │ MongoDB │ │  Redis  │
              │  :3306  │ │ :27017  │ │  :6379  │
              └─────────┘ └─────────┘ └─────────┘
```

### 2.4 容器规格一览

| 容器名 | 镜像 | 内存限制 | 端口映射 | 说明 |
|--------|------|----------|----------|------|
| `duoke-nginx` | nginx:1.24-alpine | 128M | `80:80` | 反向代理+静态资源 |
| `duoke-backend` | kaifa-backend (自构建) | 512M | `3000`(内部) | Node.js API 服务 |
| `duoke-mysql` | mysql:8.0 | 512M | `127.0.0.1:3307→3306` | 关系型数据库 |
| `duoke-mongo` | mongo:6.0 | 384M | `127.0.0.1:27017→27017` | 消息日志存储 |
| `duoke-redis` | redis:7-alpine | 192M | `127.0.0.1:6380→6379` | 缓存/会话 |

## 3. Docker Compose 快速启动

### 3.1 项目结构

```text
kaifa/
├── docker-compose.yml       # Docker Compose 编排文件
├── Dockerfile               # 后端镜像构建文件
├── .env                     # 环境变量配置
├── nginx/
│   ├── nginx.conf           # Nginx 主配置
│   └── conf.d/
│       └── default.conf     # 站点配置
├── backend/
│   ├── src/                 # 后端源码
│   ├── sql/                 # MySQL 初始化脚本
│   └── public/uploads/      # 上传文件目录
├── frontend/
│   ├── src/                 # 前端源码
│   └── dist/                # 构建产物（需手动构建）
└── mongo/
    └── init.js              # MongoDB 初始化脚本
```

### 3.2 一键启动

```bash
# 1. 构建前端（如果有修改）
cd kaifa/frontend
npm install
npm run build

# 2. 启动所有服务（首次启动会自动构建镜像）
cd kaifa
docker compose up -d

# 3. 查看启动状态
docker compose ps

# 4. 查看日志
docker compose logs -f

# 5. 验证服务
curl http://localhost/api/health
```

### 3.3 常用管理命令

```bash
# 查看所有容器状态
docker compose ps

# 查看后端日志
docker compose logs -f backend

# 查看 Nginx 日志
docker compose logs -f nginx

# 重启单个服务
docker compose restart backend

# 重新构建并启动
docker compose up -d --build

# 停止所有服务
docker compose down

# 停止并清除数据卷（危险！）
docker compose down -v
```

### 3.4 前端构建（Windows）

```powershell
# 构建脚本位置: build_frontend.ps1
cd kaifa/frontend
npm install
npm run build
# 产物输出到 frontend/dist，Nginx 自动挂载
```

### 6.1 Docker 环境 Nginx 配置（实际使用）

Docker 环境下 Nginx 作为入口网关，配置如下：

**nginx/nginx.conf**（主配置）：
```nginx
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;

events {
    worker_connections 1024;
    use epoll;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';
    access_log /var/log/nginx/access.log main;

    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    client_max_body_size 50M;

    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml application/json application/javascript application/xml+rss application/atom+xml image/svg+xml;

    include /etc/nginx/conf.d/*.conf;
}
```

**nginx/conf.d/default.conf**（站点配置）：
```nginx
upstream duoke_backend {
    server backend:3000;        # 容器间通过服务名通信
    keepalive 64;
}

server {
    listen 80;
    server_name _;

    # API代理
    location /api/ {
        proxy_pass http://duoke_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # WebSocket代理（含 WebRTC 信令）
    location /socket.io/ {
        proxy_pass http://duoke_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    # 前端静态资源
    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 健康检查
    location /health {
        proxy_pass http://duoke_backend;
        access_log off;
    }
}
```

## 9. 部署脚本（传统部署）

### 9.1 deploy.sh

```bash
#!/bin/bash
set -e

APP_NAME="duoke-backend"
APP_DIR="/data/www/duoke-backend"
BACKUP_DIR="/data/backup/duoke"

deploy() {
    cd ${APP_DIR}
    git pull origin main
    npm install --production
    npm run migrate
    pm2 reload duoke-api

    sleep 3
    if pm2 list | grep -q "duoke-api.*online"; then
        echo "部署成功！"
    else
        echo "部署失败！"
        exit 1
    fi
}

rollback() {
    local latest_backup=$(ls -t ${BACKUP_DIR}/backup_*.tar.gz | head -1)
    tar -xzf ${latest_backup} -C ${APP_DIR}
    pm2 restart duoke-api
}

case "$1" in
    deploy)   deploy ;;
    rollback) rollback ;;
    status)   pm2 list ;;
    logs)     pm2 logs duoke-api --lines 50 ;;
    *)        echo "用法: $0 {deploy|rollback|status|logs}" ;;
esac
```

### 11.3 健康检查接口

```javascript
// routes/health.js
const express = require('express');
const router = express.Router();
const db = require('../config/mysql');
const redis = require('../config/redis');
const mongoose = require('../config/mongo');

router.get('/health', async (req, res) => {
  const health = {
    status: 'ok',
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
    services: {}
  };

  // 检查MySQL
  try {
    await db.query('SELECT 1');
    health.services.mysql = 'up';
  } catch (e) {
    health.services.mysql = 'down';
    health.status = 'degraded';
  }

  // 检查Redis
  try {
    await redis.ping();
    health.services.redis = 'up';
  } catch (e) {
    health.services.redis = 'down';
    health.status = 'degraded';
  }

  // 检查MongoDB
  try {
    await mongoose.connection.db.admin().ping();
    health.services.mongodb = 'up';
  } catch (e) {
    health.services.mongodb = 'down';
    health.status = 'degraded';
  }

  const statusCode = health.status === 'ok' ? 200 : 503;
  res.status(statusCode).json(health);
});

module.exports = router;
```

## 12. 故障排查

### 12.1 Docker 环境常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 容器启动失败 | 端口冲突/资源不足 | `docker compose down` 后检查端口占用 |
| MySQL 启动慢 | WSL2 磁盘性能 | 等待 healthcheck 通过（最多 40s） |
| 后端无法连接 MySQL | 密码不匹配 | 检查 `.env` 和 `docker-compose.yml` 中的密码一致 |
| Nginx 返回 502 | 后端未就绪 | 等待 `duoke-backend` 状态变为 healthy |
| 前端构建失败 | Node 版本过低 | 使用 Node 18 LTS |
| `npm install` 慢 | 网络问题 | 配置国内镜像 `npm config set registry https://registry.npmmirror.com` |
| WebRTC 连接失败 | ICE 服务器不可达 | 检查 `WEBRTC_ICE_SERVERS` 配置 |
| TRTC 签名验证失败 | AppId/Secret 错误 | 检查腾讯云控制台 TRTC 应用配置 |
