## 1. 部署方式概览

本项目支持两种部署方式：

| 方式 | 适用场景 | 复杂度 | 本文档章节 |
|------|----------|--------|-----------|
| **Docker Compose（推荐）** | 开发/测试/小规模生产 | 低，一键启动 | 第2-6章 |
| **传统手动部署** | 大规模生产/自定义集群 | 高 | 第7-11章 |

> **当前开发环境使用 Docker Compose 部署**，5 个容器全部 healthy。后端共 28 个路由文件、43 个 MySQL 模型，全部通过。

```
                    │   :80        │
                    └──────┬───────┘

                    ┌──────▼───────┐
                    │   Backend    │  Node.js 18 + Express
                    │   :3000      │
                    └──┬───┬───┬──┘
                       │   │   │
              ┌────────▼┐ ┌▼───────▼┐ ┌────────▼┐
              │  MySQL  │ │ MongoDB │ │  Redis  │
              │  :3306  │ │ :27017  │ │  :6379  │
              └─────────┘ └─────────┘ └─────────┘
```

### 2.4 容器规格一览

| 容器名 | 镜像 | 内存限制 | 端口映射 | 说明 |
|--------|------|----------|----------|------|
| `eudazi-nginx` | nginx:1.24-alpine | 128M | `80:80` | 反向代理+静态资源 |
| `eudazi-backend` | kaifa-backend (自构建) | 512M | `3000`(内部) | Node.js API 服务 |
| `eudazi-mysql` | mysql:8.0 | 512M | `127.0.0.1:3307→3306` | 关系型数据库 |
| `eudazi-mongo` | mongo:6.0 | 384M | `127.0.0.1:27017→27017` | 补充存储（高频写入场景） |
| `eudazi-redis` | redis:7-alpine | 192M | `127.0.0.1:6380→6379` | 缓存/会话 |

## 3. Docker Compose 快速启动

### 3.1 项目结构

```text
kaifa/
├── docker-compose.yml       # Docker Compose 编排文件
├── Dockerfile               # 后端镜像构建文件
├── .env                     # 环境变量配置
├── nginx/
│   ├── nginx.conf           # Nginx 主配置
│   └── conf.d/
│       └── default.conf     # 站点配置
├── backend/
│   ├── src/                 # 后端源码
│   ├── sql/                 # MySQL 初始化脚本
│   └── public/uploads/      # 上传文件目录
├── frontend/
│   ├── src/                 # 前端源码
│   └── dist/                # 构建产物（需手动构建）
└── mongo/
    └── init.js              # MongoDB 初始化脚本
```

### 3.2 一键启动

```bash
# 1. 构建前端（如果有修改）
cd kaifa/frontend
npm install
npm run build

# 2. 启动所有服务（首次启动会自动构建镜像）
cd kaifa
docker compose up -d

# 3. 查看启动状态
docker compose ps

# 4. 查看日志
docker compose logs -f

# 5. 验证服务
curl http://localhost/api/health
```

### 3.3 常用管理命令

```bash
# 查看所有容器状态
docker compose ps

# 查看后端日志
docker compose logs -f backend

# 查看 Nginx 日志
docker compose logs -f nginx

# 重启单个服务
docker compose restart backend

# 重新构建并启动
docker compose up -d --build

# 停止所有服务
docker compose down

# 停止并清除数据卷（危险！）
docker compose down -v
```

### 3.4 前端构建（Windows）

```powershell
# 构建脚本位置: build_frontend.ps1
cd kaifa/frontend
npm install
npm run build
# 产物输出到 frontend/dist，Nginx 自动挂载
```

Docker 环境下 Nginx 作为入口网关，配置如下：

**nginx/nginx.conf**（主配置）：
```nginx
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;

events {
    worker_connections 1024;
    use epoll;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';
    access_log /var/log/nginx/access.log main;

    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    client_max_body_size 50M;

    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml application/json application/javascript application/xml+rss application/atom+xml image/svg+xml;

    include /etc/nginx/conf.d/*.conf;
}
```

**nginx/conf.d/default.conf**（站点配置）：
```nginx
upstream eudazi_backend {
    server backend:3000;        # 容器间通过服务名通信
    keepalive 64;
}

server {
    listen 80;
    server_name _;

    # API代理
    location /api/ {
        proxy_pass http://eudazi_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # WebSocket代理（含 WebRTC 信令）
    location /socket.io/ {
        proxy_pass http://eudazi_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    # 前端静态资源
    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 健康检查
    location /health {
        proxy_pass http://eudazi_backend;
        access_log off;
    }
}
```

## 9. 部署脚本（传统部署）

### 9.1 deploy.sh

```bash
#!/bin/bash
set -e

APP_NAME="eudazi-backend"
APP_DIR="/data/www/eudazi-backend"
BACKUP_DIR="/data/backup/eudazi"

deploy() {
    cd ${APP_DIR}
    git pull origin main
    npm install --production
    npm run migrate
    pm2 reload eudazi-api

    sleep 3
    if pm2 list | grep -q "eudazi-api.*online"; then
        echo "部署成功！"
    else
        echo "部署失败！"
        exit 1
    fi
}

rollback() {
    local latest_backup=$(ls -t ${BACKUP_DIR}/backup_*.tar.gz | head -1)
    tar -xzf ${latest_backup} -C ${APP_DIR}
    pm2 restart eudazi-api
}

case "$1" in
    deploy)   deploy ;;
    rollback) rollback ;;
    status)   pm2 list ;;
    logs)     pm2 logs eudazi-api --lines 50 ;;
    *)        echo "用法: $0 {deploy|rollback|status|logs}" ;;
esac
```

```javascript
// src/healthcheck.js（实际健康检查实现，server.js 注册 /api/health 路由）
const express = require('express');
const router = express.Router();
const db = require('../config/mysql');
const redis = require('../config/redis');
const mongoose = require('../config/mongo');

router.get('/health', async (req, res) => {
  const health = {
    status: 'ok',
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
    services: {}
  };

  // 检查MySQL
  try {
    await db.query('SELECT 1');
    health.services.mysql = 'up';
  } catch (e) {
    health.services.mysql = 'down';
    health.status = 'degraded';
  }

  // 检查Redis
  try {
    await redis.ping();
    health.services.redis = 'up';
  } catch (e) {
    health.services.redis = 'down';
    health.status = 'degraded';
  }

  // 检查MongoDB
  try {
    await mongoose.connection.db.admin().ping();
    health.services.mongodb = 'up';
  } catch (e) {
    health.services.mongodb = 'down';
    health.status = 'degraded';
  }

  const statusCode = health.status === 'ok' ? 200 : 503;
  res.status(statusCode).json(health);
});

module.exports = router;
```

### 12.1 Docker 环境常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 容器启动失败 | 端口冲突/资源不足 | `docker compose down` 后检查端口占用 |
| MySQL 启动慢 | WSL2 磁盘性能 | 等待 healthcheck 通过（最多 40s） |

| WebRTC 连接失败 | ICE 服务器不可达 | 检查 `WEBRTC_ICE_SERVERS` 配置 |

## 12.5 COS 防盗链与 CORS 配置（必做）

前端直传 COS 与「带签名访问 URL」方案依赖以下控制台配置，否则会出现跨域 403 或资源被盗刷：

### 1) CORS 跨域配置（前端直传/签名访问必须）
- 进入「对象存储」→ 选择 Bucket → 「安全管理」→「跨域访问 CORS 设置」。
- 新增规则：
  - 来源 Origin：`https://你的前端域名`（开发可临时加 `http://localhost:5173`）
  - 操作 Methods：`PUT`、`GET`、`POST`、`HEAD`
  - Allow-Headers：`*`（至少包含 `Content-Type`、`Authorization`）
  - 暴露 Headers：`ETag`
  - 超时 Max-Age：600

### 2) 防盗链 referer 白名单（防带宽盗刷）
- 进入「对象存储」→ 选择 Bucket → 「安全管理」→「防盗链设置」。
- 开启「防盗链」，referer 白名单填写：`https://你的域名/*`（及 `https://cdn.你的域名/*` 若有 CDN）。
- 空 referer 策略：建议「拒绝」（公开资源可放行，按需）。
- 该策略须与 Nginx `/uploads/` 的 `valid_referers` 保持一致（本地静态已配置 referer 校验，非白名单返回 403）。

### 3) 访问签名 URL（代码已内置）
- 后端 `cosSignedUrlService` 在返回动态/相册媒体时自动生成带时效的 GET 预签名 URL（默认 600s）。
- 如需调整时效，设置环境变量 `COS_SIGNED_URL_EXPIRES`（秒）。

> 以上 1)、2) 必须在腾讯云控制台手动完成，代码无法替代；3) 已由后端自动处理。
