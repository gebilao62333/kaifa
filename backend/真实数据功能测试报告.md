## 二、根因：真实库结构漂移（单一源头）

真实库 `eudazi` 从未应用过迁移脚本，缺少以下结构，导致 `authMiddleware` 查询 `xn_user` 即报 `Unknown column 'real_name'` → **所有需登录接口一律 500**（54 项失败的主因）：

| 表 | 缺失列/表 |
|---|---|
| `xn_user` | real_name, id_card, real_name_front, real_name_back, real_name_status, real_name_time |
| `xn_reserve` | duration, price, remark, service_type |
| `xn_companion_profile` | icon, description |
| `xn_game_order` | appeal_reason, appeal_time |
| `xn_post` | repost_id |
| `xn_virtual_user_tag` / `_relation` | category, is_default / is_primary |
| 缺整表 | `xn_user_visit`、`xn_user_pref`、`xn_album_like` |

**为什么重启服务也没自愈**：这些列原先只写在**手跑脚本** `sql/migrate_2026-10-01_interaction_fixes.sql` 中，未被 `runMigrations` 收录；服务启动时自动执行的迁移并不包含它。
**修复**：固化为幂等 JS 迁移 `src/migrations/20261001000001_add_interaction_fix_columns.js` 并接入 `runMigrations`（步骤 5），真实库已应用。`init_schema.sql` 经核对已完整包含上述结构（三方一致）。

## 三、真实库暴露并修复的代码缺陷

1. `GET /api/pay/recharge/list` → `xn_user is not associated to xn_order_chong`：`OrderChong` 补 `belongsTo(User,{as:'user'})`。
2. `GET /api/user/check-follow` → `UserFollow is not defined`：`user.js` 补顶层 require。
3. 钱包收入聚合：`xn_red_packet_log.money` → 真实列 `amount`。
4. 钱包支出聚合：`xn_vip_order.amount` → 真实列 `price`；管理端财务统计 VIP 汇总同修。
5. `GET /api/games/companions/:id`：查询了不存在的 `user.signature/gender/age` → 改用真实列 `dec/sex`。
6. `GET /api/region/search`：部分城市缺 `pinyin` 致 `undefined.includes` 抛错 → 服务层 null-safe。
