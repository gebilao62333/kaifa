# kaifa 文档同步

工作区根：`C:\Users\admin\Desktop\kaifa`。这个仓库的文档是验收真源（人工对照清单），不是装饰。改完代码不改对应文档 = 没人能复核。

## When to Use

- 接口签名、数据库结构、上线范围、已知限制、验证结论发生变化之后。
- 提交前自查「哪份文档描述了我改的这条代码路径」。

## Procedure

### 1. 文档地图与触发条件

| 文档 | 什么时候必须改 |
|---|---|
| `backend/后端API接口文档.md` | 新增/修改/删除任何接口；请求或响应字段、错误码、鉴权要求变化 |
| `backend/后端开发文档.md` | 目录结构、分层约定、启动/迁移流程变化 |
| `backend/数据库设计文档.md` | 新表、新字段、索引、枚举值变化（含迁移语义） |
| `backend/部署文档.md` / `Sealos部署核对清单.md` | 环境变量、镜像、端口、nginx、上线步骤变化 |
| `后端功能拆解开发指导.md` | 功能开发范围/完成度变化 |
| `前端功能差异清单.md` | 用户端/管理端功能有无、完成度变化（§11.5 是逐项修复台账） |
| `前端功能联调测试清单.md` + `前端功能联调测试报告.md` | 联调范围或结论变化（报告写"实测结果"，不是计划） |
| `未完成事项清单.md` | 新发现的缺口，或某项从"未完成"转"已完成"（不要直接删条目） |
| `人工与外部依赖验证清单.md` | 出现只能人工/外网验证的项（短信、微信支付、TURN、COS、真机） |
| `通话通道改造说明.md` / `密卡充值验证与遗留项说明.md` | 对应专项模块的变更与遗留项 |
| `eu搭子-业务闭环交互导图.html` / `前端功能导图-用户端App.md` | 业务闭环/流程变化（低频，改动大时才动） |

### 2. 做法

1. 先 `grep` 文档里现存的接口路径/字段名，找到真正的段落再改，**不要凭记忆重写整节**。
2. 保持既有格式：接口文档沿用现有的请求/响应示例块与错误码表；清单沿用现有表格列。
3. 状态变化用"更新条目 + 日期"表达，不删除历史结论（评审时能看到演进）。
4. 数字与结论必须来自真实执行：测试/探针没跑过就别写"已通过"；未验证项显式写"未验证 + 原因"。
5. 收尾自查：本次改的每个代码路径，问一句"哪份文档描述它？"没有答案才允许跳过。

### 3. 版本历史条目格式（每轮必写，格式固定）

每份主文档头部维护「文档版本 + 每轮变更行」，本轮新增**一行**、写在最上面，形如：

```markdown
> v6.30 变更：<一句话主题>——<做了什么>。<关键约束/行为变更>。**无库表/接口契约/环境变量名变更、无迁移**。新增/改写测试：<路径>，<是否执行>。遗留：<如实标注>。详见《<依据文档>》发现清单第 <N> 条
```

硬要求：
- 版本号递增（后端文档 `v6.x`、API `v6.x.y`、数据库 `v6.x`、部署 `v6.x`、前端技术 `v7.x`），**同一轮多份文档一起加**，不要只改一份。
- 行内必须点名：改了什么层、**有没有库表/接口契约/环境变量变更**、测试是否真跑（跑过写命令与结果，没跑写「未执行 + 原因」）、遗留项。
- 配套的《未完成事项清单》与《前端功能差异清单》§11.5 用**编号**互相引用，编号递增不复用。

### 4. PowerShell 下的检索姿势

```powershell
Select-String -Path backend\后端API接口文档.md -Pattern '/api/vip/packages' -Encoding UTF8
Select-String -Path *.md,backend\*.md -Pattern 'M-12' -Encoding UTF8
(Get-Content 未完成事项清单.md -Encoding UTF8).Count
```

## Verification

- 本次改动的每条代码路径都能指到一份文档的具体小节。
- 版本历史行已加、编号连续、日期正确。
- 未验证项写清了原因，没有把「计划」写进「报告」。

## Pitfalls

- 只改报告不改清单（或反之）→ 两边口径打架，下次联调按清单执行就会踩空。
- 把计划写进"报告"：报告只放实测结果与证据路径。
- 接口文档写全了，但数据库设计文档没记新字段 → 后续迁移与联调对不上。
- 忘了同步版本历史行 → 下一次评审无法判断哪一轮引入了该行为。
